API Reference

REST API

A small JSON/REST API. All amounts are in the asset's smallest base units (wei for 18-dp assets, e.g. 1000000 = 1 USDC at 6 dp). All timestamps are Unix ms unless noted.

Base URL & conventions

  • Base URL — https://liquidflow-io.vercel.app
  • Auth — merchant/payment endpoints take Authorization: Bearer <api_key>
  • Chains — eip155:1 (Ethereum), eip155:137 (Polygon), eip155:8453 (Base)
  • Assets — VERSE on Ethereum, fxVERSE on Polygon, and canonical USDC on Ethereum, Polygon and Base.
  • Decimals — VERSE/fxVERSE 18 · USDC 6. Send amount as a positive integer in base units.
Security status: internally reviewed and tested, but not independently certified. Use controlled values until the external audit and mainnet rehearsal are complete. See Audit.

Merchants

POST /api/merchants

Create a merchant and receive an API key. LiquidFlow provisions 10 merchant-owned receiving wallets plus one primary Privy wallet.

curl -X POST https://liquidflow-io.vercel.app/api/merchants \
  -H "Content-Type: application/json" -d '{
  "name": "Acme",
  "mode": "wallet_pool",
  "chains": ["eip155:1", "eip155:137", "eip155:8453"],
  "settle": "USDC",
  "payout": "",
  "webhook": "https://acme.com/lf/hook"
}'
# Returns an active merchant_id, api_key, webhook_secret, and primary wallet. No subscription or activation payment is required.

GET /api/merchants

Authenticated. Returns the active merchant profile (name, mode, chains, payout, webhook secret, created_at).

Payments

POST /api/payments

Authenticated. Creates a payment using the next available merchant payment wallet as the deposit address.

curl -X POST https://liquidflow-io.vercel.app/api/payments \
  -H "Authorization: Bearer lf_live_…" \
  -H "Content-Type: application/json" -d '{
  "amount": "1000000",
  "asset": "USDC",
  "chain": "eip155:137",
  "label": "Order #1024"
}'
# Returns payment_id, deposit_address, amount, asset, chain, status and expires_at.

GET /api/payments

Authenticated. Lists the merchant's payments plus stats. Confirms any pending deposit that has landed on-chain (on-demand).

# Returns { "payments":[…], "stats":{"total","confirmed","pending","volume"} }

GET /api/payments/:id

Returns one payment's status and runs an on-demand finality-aware chain check. Merchant payments require the owning key. Possible states include awaiting_payment, awaiting_topup, checking_finality, confirmed, refund_pending, manual_review, expired and cancelled.

curl https://liquidflow-io.vercel.app/api/payments/pay_… \
  -H "Authorization: Bearer lf_live_…"

# Release goods only when the returned status is "confirmed".

POST /api/simulate/:id

Internal development helper only. It is disabled in production and requires both ALLOW_TEST_CONFIRM=1 and the server-side test secret. A merchant API key cannot simulate confirmation.

Liquidity unification

POST /api/dex/quote

Authenticated. Builds a merchant-signed same-chain swap plan. Verse DEX is the primary route for Ethereum VERSE/USDC. QuickSwap is the approved Polygon liquidity fallback for fxVERSE/USDC when a native Verse DEX Polygon route is unavailable. LiquidFlow never signs or relays the swap.

curl -X POST https://liquidflow-io.vercel.app/api/dex/quote \
  -H "Authorization: Bearer lf_live_…" \
  -H "Content-Type: application/json" -d '{
  "chain":"eip155:1", "from":"VERSE", "to":"USDC",
  "amount":"1000000000000000000", "recipient":"0x…",
  "slippage_bps":50
}'
# Returns an exact approval (if needed), protected swap calldata,
# minimum output, price impact, allowlisted path and 10-minute deadline.

Safety limits: slippage 0.1–3%, cumulative pool impact ≤5%, trade size ≤10% of each reserve, canonical tokens only, and runtime router/factory identity checks.

Fundraisers (Potlock)

POST /api/fundraisers

Create a fundraiser with a creator-owned primary Privy wallet. Returns a shareable URL, dashboard key, and wallet address.

curl -X POST https://liquidflow-io.vercel.app/api/fundraisers \
  -H "Content-Type: application/json" -d '{
  "title": "Rebuild the library", "description":"…",
  "goal": 2, "chain": "eip155:137", "asset": "USDC"
}'
# Returns id, slug, share URL and the one-time spend key.

GET /api/fundraisers

Public list of campaigns with live totals (computed from confirmed on-chain donations).

GET /api/fundraisers/:id

Campaign details: raised, pct, donation_count, recent[], symbol, decimals.

POST /api/fundraisers/:id

Create a direct donation request. Body { "amount": "<base units>" } → returns the next available campaign payment-wallet deposit_address.

Payroll

The business deploys its own PayrollScheduler (native) or PayrollSchedulerERC20 (USDC) contract from its wallet, then registers it so Liquid Flow's trigger key can automate due releases. See Security for the non-custodial guarantee.

POST /api/payroll

curl -X POST https://liquidflow-io.vercel.app/api/payroll \
  -H "Content-Type: application/json" -d '{
  "contract": "0x…",  "company": "0x…", "name": "Acme payroll",
  "token": "0x1c7D…7238", "decimals": 6, "symbol": "USDC"
}'

GET /api/payroll?company=0x…

List a company's payroll contracts.

GET /api/payroll/:contract

Reads the contract's payouts + balances from chain and runs the on-demand keeper — releasing any due, company-defined payouts via the trigger key (batched for ERC-20). Add ?readonly=1 to read without triggering.

Webhooks

When a payment confirms, Liquid Flow POSTs a JSON event to your webhook URL:

{ "type":"payment.confirmed", "payment_id":"pay_…", "amount":"1000000",
  "asset":"USDC", "chain":"eip155:137", "confirmations":128, "final":true }

Each request carries a signature header. Verify it with your webhook_secret:

Header:  LF-Signature: t=<ms>,v1=<hex>
signed = HMAC_SHA256(webhook_secret, `${t}.${rawBody}`)   // compare to v1

// Node
const [ts,v1] = header.split(',').map(s=>s.split('=')[1]);
const expected = crypto.createHmac('sha256', secret).update(`${ts}.${raw}`).digest('hex');
const ok = crypto.timingSafeEqual(Buffer.from(v1), Buffer.from(expected));

Reject if the signature fails or the timestamp is stale. Treat duplicate LF-Webhook-Id values idempotently, and verify payment status with GET /api/payments/:id before releasing high-value goods.
